# 让 LyreBot 能从录音生成曲谱

从 GitHub 拉下来的 LyreBot 可以直接弹曲谱、从 MIDI 编配、记录演奏，但「从录音生成曲谱」（▶ 左边的 ● 按钮，以及把音频文件放进 `midi` 文件夹自动转谱）还要另外装两样东西。它们体积大，许可证也和 LyreBot 不同，所以没有放进仓库：

- [audio.cpp](https://github.com/0xShug0/audio.cpp)：把录音转成 MIDI 的程序，Apache-2.0 许可证。
- MuScriptor Medium 模型：audio.cpp 转录时用的模型，CC BY-NC 4.0 许可证，只能用于非商业用途。

一共要下载约 1.3 GB，装好后占约 1.5 GB 硬盘空间。下面的步骤照做一遍就行，不用登录任何网站，也不用装 Python 包。

## 需要的电脑

- 64 位的 Windows 10 或 11，装有 Python 3.11 或更新版本（LyreBot 本身就要求这个）。
- 内存最好有 16 GB。转录时 audio.cpp 要占 4～5 GB 内存，超过 6 GB 时 LyreBot 会把它停掉。
- 有一块支持 Vulkan 的显卡会快很多（近几年的 NVIDIA、AMD、Intel 独立显卡和核显，驱动不太旧就行）：100 秒的录音约 18 秒转完。没有也可以，只用处理器转，时间约为录音长度的 1.6 倍。

## 第 1 步：确认 LyreBot 本身能用

在拉下来的 LyreBot 文件夹里双击 `LyreBot.vbs`，能看到曲目列表就行，然后先关掉它。打不开的话先按 [README](../README.md) 开头的「使用」一节把它跑起来，录音功能是在这之上加的。

## 第 2 步：在 LyreBot 文件夹里建一个 `tools` 文件夹

LyreBot 文件夹就是放着 `LyreBot.vbs`、`lyrebot`、`txt`、`midi` 的那个文件夹。在里面新建一个文件夹，名字叫 `tools`。

`tools` 已经写在仓库的 `.gitignore` 里，以后 `git pull` 更新 LyreBot 时不会动它，也不会被提交上去。

## 第 3 步：下载 audio.cpp，解压到 `tools` 里

下载这两个 zip（v0.9.3 是测试过的版本）：

- 显卡版：[audio-v0.9.3-bin-windows-x64-vulkan.zip](https://github.com/0xShug0/audio.cpp/releases/download/v0.9.3/audio-v0.9.3-bin-windows-x64-vulkan.zip)（约 82 MB）
- 处理器版：[audio-v0.9.3-bin-windows-x64-cpu.zip](https://github.com/0xShug0/audio.cpp/releases/download/v0.9.3/audio-v0.9.3-bin-windows-x64-cpu.zip)（约 31 MB）

两个都要。LyreBot 先用显卡版，显卡用不了时自动改用处理器版；显卡版自己不一定能改用处理器，所以只放显卡版不保险。没有独立显卡的电脑也照样两个都放。

右键显卡版的 zip，选「全部解压缩」，把目标文件夹改成 `LyreBot文件夹\tools\audiocpp-vulkan`，点「提取」；处理器版同样解压到 `LyreBot文件夹\tools\audiocpp-cpu`。zip 里的文件没有外层文件夹，解压完应当正好是：

```text
tools\audiocpp-vulkan\audiocpp_cli.exe
tools\audiocpp-cpu\audiocpp_cli.exe
```

（旁边还有一堆 dll、`model_specs` 文件夹等，全部留着。）

注意这两点，否则 LyreBot 找不到它：

- `audiocpp_cli.exe` 只能在 `tools` 下面正好一层的文件夹里。如果解压时多出了一层文件夹，变成 `tools\audiocpp-vulkan\audio-v0.9.3-bin-windows-x64-vulkan\audiocpp_cli.exe`，就把最里面那层的文件全部挪上来一层。
- 文件夹名里带 `vulkan` 的当作显卡版，带 `cpu` 的当作处理器版。照上面起名就不会错。

## 第 4 步：下载模型，放进 `tools\models`

在 `tools` 里新建 `models` 文件夹，把这个文件下载进去：

- [muscriptor-medium-f32.gguf](https://huggingface.co/audio-cpp/audio.cpp-gguf/resolve/main/MuScriptor-Small-GGUF/muscriptor-medium-f32.gguf)（约 1.2 GB，不用登录）

它在 Hugging Face 的 [audio-cpp/audio.cpp-gguf](https://huggingface.co/audio-cpp/audio.cpp-gguf/tree/main/MuScriptor-Small-GGUF) 仓库里。那个文件夹虽然叫 `MuScriptor-Small-GGUF`，里面放着 Small、Medium、Large 三个模型，要下的是 **Medium**。下载下来的文件名不要改，名字里必须带 `muscriptor`，扩展名必须是 `.gguf`。

**不要下载 Large**（`muscriptor-large-f32.gguf`，5.5 GB）。`tools` 里有好几个模型时，LyreBot 会用文件最大的那个，而 Large 转录时要的内存超过 6 GB，每次都会被停掉。

内存只有 8 GB 的电脑可以改下 Small（[muscriptor-small-f32.gguf](https://huggingface.co/audio-cpp/audio.cpp-gguf/resolve/main/MuScriptor-Small-GGUF/muscriptor-small-f32.gguf)，约 400 MB，转录时约占 3.5 GB 内存）。它比 Medium 快一倍多，但转得没那么准。两个都放的话用的是 Medium。

装完以后 LyreBot 文件夹应该是这样：

```text
LyreBot\
  LyreBot.vbs
  lyrebot\
  midi\
  txt\
  tools\
    audiocpp-vulkan\
      audiocpp_cli.exe
      （其他 dll 和文件夹）
    audiocpp-cpu\
      audiocpp_cli.exe
      （其他 dll 和文件夹）
    models\
      muscriptor-medium-f32.gguf
```

## 第 5 步：检查 LyreBot 能不能找到它们

在 LyreBot 文件夹的地址栏里输入 `cmd` 回车，打开一个命令行窗口，运行：

```bat
python -c "from pathlib import Path; from lyrebot.transcribe import find_tools, tool_folders; print(find_tools(tool_folders(Path.cwd())))"
```

（提示找不到 `python` 的话，把开头的 `python` 换成 `py -3`。）

装对了会打印很长的一行，开头是 `Tools(attempts=`。在里面找这三样：`audiocpp-vulkan\\audiocpp_cli.exe` 后面跟着 `'vulkan'`，`audiocpp-cpu\\audiocpp_cli.exe` 后面跟着 `'cpu'`，`model=WindowsPath(...)` 里是 `muscriptor-medium-f32.gguf`。只打印 `None` 就是没找到，回去对照第 3、4 步的目录。末尾的 `ffmpeg=None` 不要紧，见后面的「MP3 等格式」。

## 第 6 步：录一首试试

1. 双击 `LyreBot.vbs` 启动，点 ▶ 左边的 ●。
2. 弹出输入框时填上曲名，比如 `春日影`。如果弹出的是「还不能录音」，说明工具没找到，回到第 5 步。
3. 在别处播放想转的音乐，视频网站、音乐播放器、游戏里的背景音乐都可以。LyreBot 录的是电脑扬声器正在放的声音，所以先关掉其他会出声的东西。有声音时才开始录；点 ■、安静 5 秒或录满 10 分钟时结束。
4. 录完后底部会显示「正在把 春日影-录音.wav 转成 MIDI…」。转录在后台进行，这时照样可以弹别的曲子（不过弹琴时不会开始新的转录）。
5. 转完后列表里多出「春日影-录音」并自动选中，就可以弹了。录音、MIDI 分别留在 `midi\春日影-录音.wav` 和 `midi\春日影-录音.mid`，曲谱在 `txt\春日影-录音.txt`。

不想录音的话，也可以直接把一个 WAV 文件放进 `midi` 文件夹，LyreBot 开着时一两秒后就开始转；没开着时下次启动时转。

录音转出来的曲谱只求弹起来和原曲一样，节拍和小节线不一定规整。钢琴独奏转得最好，配器复杂的曲子（乐队、电子乐）只能当作手改的底稿，转完先听一遍。

## MP3 等格式

点 ● 录下来的是 WAV，不需要别的东西。要把 MP3、FLAC、M4A、OGG 直接放进 `midi` 转谱，还需要 [ffmpeg](https://ffmpeg.org/download.html)。装好后让 `ffmpeg` 能在命令行里直接运行（加进 PATH），或者把 `ffmpeg.exe` 放进 `tools` 里任何一个文件夹，比如 `tools\ffmpeg\ffmpeg.exe`。不想装的话，先用别的软件把音频转成 WAV 再放进去。

## 出问题时

**点 ● 弹出「还不能录音」**：工具或模型没找到。按第 5 步检查，最常见的是 `audiocpp_cli.exe` 多套了一层文件夹，或者模型文件被改了名、下载没完成（Medium 应该是 1,228,154,944 字节，约 1.14 GB）。

**底部提示转录失败**：显卡版出错时，LyreBot 会自动再用处理器版转一遍，所以先确认 `audiocpp-cpu` 放好了。处理器版也闪退的话（一些老处理器会这样），把 `audiocpp-cpu` 里的文件换成 [audio-v0.9.3-bin-windows-x64-cpu-portable.zip](https://github.com/0xShug0/audio.cpp/releases/download/v0.9.3/audio-v0.9.3-bin-windows-x64-cpu-portable.zip) 里的。显卡版老出错时，更新一下显卡驱动通常就好了。

**提示「转录占用的内存超过 6 GB，已停止」**：先关掉占内存的程序（比如游戏）再转，或者换成 Small 模型。检查 `tools` 里有没有误下的 Large。

**提示「转录超过 30 分钟还没完成，已停止」**：一般是没有显卡、只用处理器转很长的录音。把录音截短，或者换 Small。

**改好以后，失败过的录音还是不转**：转录失败的录音，LyreBot 这次开着时不会再试，关掉重开就会重新转。

**已经转过的录音想重新转**：同名的 MIDI 或曲谱已经存在时，LyreBot 不会再转。删掉 `midi` 里同名的 `.mid`，再删掉由它编出来的曲谱（挪进了 OST 或歌曲的文件夹、或改过名的也算），留下 `.wav`，它就会重新转。

**同一台电脑上有好几份 LyreBot**：可以不在每份里放 `tools`，而是在 LyreBot 文件夹旁边建一个叫 `LyreBot-tools` 的文件夹，里面的放法和 `tools` 一样，几份 LyreBot 都会去那里找。

更新的 audio.cpp 版本多半也能用，但没有测过。换了新版本出问题时，换回上面的 v0.9.3。转录和编配是怎么做的、准确度如何，见 [原理与开发记录](原理与开发记录.md)。
